# Session Log: 2026-04-08_02

## 1. 개요 (Context)

- **주요 목적:** 실시간 채팅 메시지 DB 영속화(저장) 및 과거 대화 내역 조회 API 구현.

## 2. 주요 작업 및 결정 사항 (Decisions)

### [Database] 채팅 데이터 구조화
- **`CHAT_MESSAGE` 테이블 보완:** 여러 채팅방을 구분하기 위한 `ROOM_ID` 컬럼 추가 및 인덱싱 고려.
- **Model/DTO 분리:** DB 엔티티인 `ChatMessage`와 API 응답용 `ChatMessageResponse`를 분리하여 도메인 중심 설계 유지.

### [Backend] 채팅 영속화 및 시스템 안정성 고도화
- **`WebSocketController` 수정:** 메시지 수신 시 `MemberMapper`를 활용하여 발신자의 닉네임(`senderName`)을 실시간 매핑 발송. 불필요한 `QUIT` 수동 처리 로직을 제거하고 시스템 이벤트를 활용하도록 일원화.
- **입장(ENTER) 처리:** 서버 사이드에서 `"{userName}님이 입장하셨습니다."` 문구 강제 생성 및 전체 브로드캐스트 적용.
- **자동 퇴장(QUIT) 감지 시스템 구축:** 
    - **`WebSocketEventListener` 신설:** `SessionDisconnectEvent`를 구독하여 브라우저 종료 및 강제 연결 해제 시에도 퇴장 알림이 발송되도록 구현.
    - **데이터 캐싱 (StompHandler):** 연결(`CONNECT`) 시점에 사용자 정보(ID, 닉네임)를 `SessionAttributes`에 저장하여, 연결 해제 시 DB 조회 없이 즉시 메시지 생성이 가능하도록 최적화.
    - **중복 발송 방지 (AlreadyLeft Marking):** 동일 세션에 대해 이벤트가 중복 발생할 경우를 대비하여 `alreadyLeft` 마킹 로직을 추가, 사용자에게 중복 메시지가 노출되는 현상 차단.
- **히스토리 조회 쿼리 고도화:** `Chat.xml`에서 `MEMBER_INFO` 테이블과 `LEFT JOIN`을 사용하여 닉네임 포함 대화 내역 원샷 조회 구현.

### [Debugging] 이슈 추적 및 해결
- **중복 로그 분석:** 서버 로그 분석을 통해 프론트엔드에서 동일 세션이 중복 연결(`Double Connection`)되고 있음을 파악 및 대응 가이드 마련.
- **Redis 채널명 일원화:** `"realtime-message"`로 오설정된 채널명을 `"realtime"`으로 통일하여 메시지 전파 오류 해결.

### [Refactoring] DTO 필드 확장
- **DTO 일관성:** `RealTimeMessage`, `ChatMessage`, `ChatMessageResponse` 세 곳에 `senderName` 필드를 추가하여 기술 스택 전반의 데이터 일관성 확보.
