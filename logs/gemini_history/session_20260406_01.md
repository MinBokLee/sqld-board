## 2. 주요 작업 및 결정 사항 (Decisions)

### [Infrastructure] WebSocket & STOMP 설정
- **STOMP 프로토콜 도입:** 단순 WebSocket보다 규격화된 메시징 처리를 위해 STOMP 사용.
- **브로커 설정 (`WebSocketConfig`):** 
    - `/sub` (구독): 메시지 수신 경로.
    - `/pub` (발행): 메시지 송신 경로.
    - `/ws-stomp`: 연결 엔드포인트 및 SockJS 지원 설정.

### [Security] JWT 보안 연동
- **`StompHandler` (Interceptor):** WebSocket 연결 시(`CONNECT`) HTTP 헤더의 JWT를 검증하는 커스텀 인터셉터 구현.
- **사용자 식별:** 검증 성공 시 토큰에서 `memberId`를 추출하여 `accessor.setUser()`를 통해 세션에 고정.
- **Security Bypass:** 핸드쉐이크 및 SockJS 정보를 위해 `/ws-stomp/**` 경로를 보안 필터에서 제외(`permitAll`).

### [Scaling] Redis Pub/Sub 메시지 중계
- **멀티 서버 대응:** Redis를 메시지 브로커로 사용하여 서버가 늘어나도 모든 접속자에게 메시지가 전달되도록 설계.
- **`RedisSubscriber`:** Redis 채널(`realtime`)에서 메시지를 수신하여 각 사용자의 WebSocket 채널(`/sub/...`)로 분산 발송.

### [Controller] 메시지 핸들러 구현
- **`WebSocketController`:** `@MessageMapping`을 통해 클라이언트 메시지 수신.
- **JSON 직렬화:** `ObjectMapper`를 사용하여 `RealTimeMessage` 객체를 JSON 문자열로 변환 후 Redis로 발행하여 기존 조회수 로직(String 기반)과의 호환성 유지.

## 3. 해결된 주요 오류 (Troubleshooting)
- **401/403 Forbidden:** Spring Security가 WebSocket 초기 연결을 차단하는 문제 -> `/ws-stomp/**` 경로 권한 허용으로 해결.
- **CORS (null origin):** 브라우저에서 로컬 파일 실행 시 발생하는 CORS 에러 -> `setAllowedOriginPatterns("*")` 적용.
- **ClassCastException:** RedisTemplate이 객체를 직접 직렬화하지 못하는 문제 -> `ObjectMapper`로 수동 직렬화하여 해결.
