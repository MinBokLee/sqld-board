## 2. 주요 작업 및 결정 사항 (Decisions)

### [Core Features] 페이징 및 검색 고도화
- **동적 페이지 사이즈 도입**: 사용자가 10, 30, 50, 100개씩 보기를 선택할 수 있도록 `size` 파라미터 연동 및 서버 측 안전장치(최대 100개 제한) 구현.
- **통합 검색(Keyword) 연동**: "내가 쓴 글" 및 "스크랩 리스트"에 `keyword` 파라미터를 추가하고, DB의 전문 검색(Full-Text Search) 인덱스를 활용한 `MATCH...AGAINST` 쿼리 적용.
- **정확한 페이징 로직 수정**: 
    - 검색 결과에 따라 하단 페이징 번호가 어긋나지 않도록 `getBoardTotalCount` 및 `getSearchScrapTotalCount`에도 검색 조건을 완벽히 일치시킴.
    - `totalPage` 계산 시 현재 리스트 크기가 아닌 요청된 `size`를 분모로 사용하여 마지막 페이지에서 페이지 수가 널뛰는 버그 해결.

### [Performance] 상세 페이지 딜레이 분석 및 대책
- **원인 분석**: 상세 조회 시 발생하는 5회의 DB 호출(특히 조회수 UPDATE의 Row Lock과 댓글 COUNT 서브쿼리)이 병목임을 확인.
- **최적화 전략**: 
    - **Redis 도입 결정**: 조회수 증가 로직을 메모리 기반의 Redis로 이관하여 DB 쓰기 부하를 줄이기로 함.
    - **반정규화 고려**: 댓글 수를 `BOARD` 테이블에 컬럼으로 관리하여 조회 성능을 높이는 방안 도출.

### [Database] 스크랩 조회 쿼리 최적화
- **데이터 무결성**: 스크랩 총 개수 조회 시 `BOARD` 테이블과 `INNER JOIN`을 수행하여 삭제된 게시글(`DELETE_YN = 'N'`)은 카운트에서 제외하도록 수정.
- **쿼리 안정성**: SQL 오타(`COUT`) 수정 및 `LIMIT/OFFSET` 누락 해결.
