# Session Log: 2026-04-03_01

## 1. 개요 (Context)
- **일시:** 2026-04-03
- **주요 목적:** Redis 기반 조회수(View Count) 캐싱 및 지연 업데이트(Delayed Update) 시스템 구축을 통한 DB 부하 감소 및 성능 최적화.

## 2. 주요 작업 및 결정 사항 (Decisions)

### [Infrastructure] Redis 도입 및 설정
- **의존성 추가:** `spring-boot-starter-data-redis` 도입.
- **설정 커스터마이징 (`RedisConfig`):** 
    - `RedisTemplate<String, Object>` 빈 등록.
    - `StringRedisSerializer`를 Key와 Value 모두에 적용하여 가독성 및 디버깅 편의성 확보. (중복 설정 오류 수정 완료)
- **환경 분리:** `application-dev.yml`에 로컬 Redis 연결 정보 설정.

### [ViewCount] 캐싱 및 지연 업데이트 로직
- **원자적 증가 (`ViewCountRedisService`):** Redis의 `INCR` 명령어를 사용하여 동시성 이슈 없이 조회수를 1씩 증가시키는 로직 구현.
- **지연 업데이트 (`ViewCountScheduler`):** 
    - `@Scheduled`를 활용하여 Redis에 쌓인 조회수를 일정 주기마다 DB에 일괄 합산(`UPDATE BOARD SET VIEW_COUNT = VIEW_COUNT + #{count}`).
    - DB 반영 후 Redis 키를 삭제하여 데이터 정합성 유지.
- **실시간성 보장:** 상세 조회(`getSearchBoard`) 및 모든 목록 조회(`getBoardListWithPaging`, `getBoardMyList`, `searchBoardContent`) 시 `DB 데이터 + Redis 미반영 데이터`를 합산하여 반환하도록 개선.

### [Optimization] 로컬 캐시 튜닝
- **Caffeine Cache 조정:** 인기 게시물(`popularPosts`)의 캐시 만료 시간을 기존 10분에서 **1분**으로 단축. 
    - **사유:** DB 부하 감소 효과는 유지하면서 사용자가 느끼는 조회수 오차(상세 페이지 vs 목록 페이지)를 최소화하기 위함.

## 3. 해결된 주요 오류 (Troubleshooting)
- **SerializationFailedException:** `RedisConfig`에서 `setValueSerializer` 설정이 누락되거나 중복 코드로 인해 자바 객체 직렬화 오류 발생 -> `StringRedisSerializer`로 통일하여 해결.
- **데이터 불일치 현상:** 상세 페이지와 목록 페이지의 조회수가 다르게 보이는 문제 -> 모든 목록 조회 서비스 로직에 Redis 합산 루프를 추가하여 해결.
- **중복 호출 방지:** 기존의 `/countView` 컨트롤러 엔드포인트를 상세 조회 API 내부로 통합하여 네트워크 요청 횟수 최적화.
