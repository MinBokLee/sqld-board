## 📝 작업 개요
- **일시:** 2026-05-14
- **주요 목표:** Dev/Prod 환경 간의 Redis 데이터 간섭 해결 및 배포 환경(502 에러) 정상화

## 🛠️ 주요 작업 내용

### 1. 보안 및 연결 이슈 해결
- **HTTP 401/CORS 진단:** 백엔드 주소 직접 접근 시 발생하는 401 에러가 보안 설정상 정상임을 확인하고, 로컬 프론트엔드와 원격 백엔드 간의 통신 구조 검증.
- **SSL/프로토콜 미스매치 수정:** 프론트엔드에서 `https`로 잘못 호출하던 Base URL을 `http://175.197.69.42:8881`로 수정 가이드하여 `ERR_CERT_COMMON_NAME_INVALID` 에러 해결.

### 2. Redis 환경별 데이터 격리 (핵심 작업)
- **문제 상황:** 동일한 Redis 서버 및 채널(`realtime`) 공유로 인해 Prod 알림이 Dev 서버에 뜨는 현상 발생.
- **해결 방안:**
    - `application-dev.yml` / `application-prod.yml`에 환경별 토픽 설정 추가 (`realtime-dev`, `realtime-prod`).
    - `RedisConfig`, `WebSocketEventListener`, `NotificationStompController`, `NotificationStompServiceImpl`, `WebSocketServiceImpl` 전면 수정.
    - `@Value("${spring.data.redis.topic}")`을 도입하여 하드코딩된 `"realtime"` 문자열 제거 및 동적 토픽 적용.
- **접속자 명단(Presence) 분리:** Redis Key 생성 로직(`getPresenceKey`)에 환경별 토픽명을 포함시켜(`chat:presence:realtime-prod:roomId`) 데이터 완전 격리.

### 3. 배포 트러블슈팅
- **502 Bad Gateway 진단:** 도커 로그 분석을 통해 `${spring.data.redis.topic}` 설정 누락으로 인한 컨테이너 실행 실패 확인.
- **포트 맵핑 교정:** CI/CD 스크립트(`docker run`)의 포트 설정을 앱 설정(`8080`)과 Nginx 설정에 맞춰 교정 제안.

## 🏁 최종 상태

- **코드 완결성:** `@Value` 참조 경로 오류 및 오타(따옴표 등) 전수 검사 및 수정 완료.
